# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
npm start                 # start the Metro dev server
npm run ios               # build and run the iOS app (Simulator)
npm run android           # build and run the Android app (Emulator)
npm run lint              # run ESLint
npm test                  # run the Jest test suite
npx jest __tests__/App.test.tsx   # run a single test file
npx jest -t "renders correctly"   # run tests matching a name pattern
```

iOS native deps use CocoaPods, managed via the Ruby bundler:

```sh
bundle install                 # install CocoaPods itself (first run only)
bundle exec pod install         # install/update pods (after native dep changes)
```

Metro must be running (`npm start`) before/while launching `npm run ios` or `npm run android`; the CLI will start it automatically if it isn't already running, but keeping it in its own terminal makes logs easier to read.

## Architecture

This is a React Native CLI project (not Expo) bootstrapped from `@react-native-community/cli`.

- `index.js` registers the root component (`App`, from `App.tsx`) under the app name defined in `app.json` via `AppRegistry.registerComponent`. This is the sole native/JS entry point on both platforms.
- `App.tsx` wraps the app in `SafeAreaProvider` (from `react-native-safe-area-context`) and `NavigationContainer` (from `@react-navigation/native`), then renders `src/navigation/RootNavigator`. Any new top-level UI should stay inside `SafeAreaProvider` to get correct safe-area handling on notched devices.
- `android/` and `ios/` contain the native project shells (Gradle / Xcode + CocoaPods) generated by the CLI. Native code changes belong here; JS/TS logic belongs at the repo root.

### Navigation

- `src/navigation/types.ts` defines the two typed param lists: `RootStackParamList` (`Login`, `Home`) and `HomeTabParamList` (`Dashboard`, `Transactions`, `Settings`). Add new screens/tabs here first so navigation calls stay type-checked.
- `src/navigation/RootNavigator.tsx` is a `@react-navigation/native-stack` navigator (headers hidden) that starts on `Login` and swaps to `Home` on successful auth via `navigation.replace('Home')` — `replace` (not `navigate`) so the back gesture can't return to the login screen.
- `src/screens/HomeScreen.tsx` is a `@react-navigation/bottom-tabs` navigator nesting `DashboardScreen`, `TransactionsScreen`, `SettingsScreen`. Tab icons come from the `TAB_ICONS` emoji map rendered through a module-level `TabIcon` component — icons are plain emoji glyphs (no icon-font library installed), so `tabBarIcon`'s `color` prop has no visible effect on them.
- Cross-tab navigation (e.g. Dashboard's "See all" linking to the Transactions tab) uses `useNavigation<BottomTabNavigationProp<HomeTabParamList>>()`.

### Auth

- `src/auth.ts` is the whole auth layer: `login(email, password)` sends `GET {API base}/api/wanaka/accounts/login` with `Authorization: Basic <base64(email:password)>` (base64-encoded via the `base-64` package, since Hermes doesn't polyfill `btoa`), then persists the response's `accesstoken`/`refreshtoken` in the **iOS Keychain / Android Keystore** via `react-native-keychain` (never AsyncStorage — tokens must stay encrypted at rest). `getAccessToken()` reads it back for authenticated requests elsewhere; `logout()` clears it.
- The login endpoint currently points at `http://localhost:3001`. iOS allows this via `NSAllowsLocalNetworking` in `Info.plist`; Android debug builds allow cleartext traffic via the templated `usesCleartextTraffic` in `AndroidManifest.xml`. Neither needed manual changes — don't add ATS/cleartext exceptions unless the endpoint moves off loopback.
- `src/screens/LoginScreen.tsx` calls `login()`; `src/screens/SettingsScreen.tsx`'s "Log Out" button calls `logout()` and navigates back to `Login`.

### Data layer

- `data/transactions.ts` holds the `Transaction` type, a static mock dataset (dates generated relative to "today" via `daysAgo()`), and the selectors every screen reads through: `getBalance`, `getIncomeTotal`, `getExpenseTotal`, `getSortedByDateDesc`, plus `formatCurrency`/`formatDate`. When a real transactions API exists, swap the data source inside this file (screens already consume it only through these selectors, not the raw array).
- `components/TransactionRow.tsx` is the shared list-row renderer used by both `DashboardScreen` (top 5 recent) and `TransactionsScreen` (full list) — keep transaction-row UI changes here rather than duplicating per screen.

### Tooling notes

- Path aliases/module resolution: none configured — Metro uses `@react-native/metro-config` defaults with no custom `resolver` settings in `metro.config.js`.
- TypeScript config (`tsconfig.json`) extends `@react-native/typescript-config`; Babel config extends `@react-native/babel-preset`. Don't add custom transforms/aliases without updating both if JS behavior needs to match TS resolution.
- Linting extends `@react-native` ESLint config (`.eslintrc.js`); formatting rules (`.prettierrc.js`) use single quotes, trailing commas everywhere, and `avoid` arrow-paren style — match these when writing new code. `react/no-unstable-nested-components` is enforced, which is why tab-icon rendering is a module-level component rather than an inline arrow function in `screenOptions`.
- `jest.config.js` extends `@react-native/jest-preset`'s `transformIgnorePatterns` to also transform `@react-navigation` and `react-native-screens` (both ship untranspiled ESM in `node_modules`) — extend this pattern again if a future dependency fails Jest with `SyntaxError: Unexpected token 'export'`.
- Tests use `@react-native/jest-preset` with `react-test-renderer`; `__tests__/App.test.tsx` is the only test currently and just smoke-renders `App` inside its real navigation tree.

Requires Node >= 22.11.0 (per `package.json` `engines`).
