## Commands

```sh
npm start                 # start the Metro dev server
npm run ios               # build and run the iOS app (Simulator)
npm run android           # build and run the Android app (Emulator)
npm run lint              # run ESLint
npm test                  # run the Jest test suite
npx jest __tests__/App.test.tsx   # run a single test file
npx jest -t "renders correctly"   # run tests matching a name pattern
```

iOS native deps use CocoaPods, managed via the Ruby bundler:

```sh
bundle install                 # install CocoaPods itself (first run only)
bundle exec pod install         # install/update pods (after native dep changes)
```

Metro must be running (`npm start`) before/while launching `npm run ios` or `npm run android`; the CLI will start it automatically if it isn't already running, but keeping it in its own terminal makes logs easier to read.

## Architecture

This is a React Native CLI project (not Expo) bootstrapped from `@react-native-community/cli`, currently at the initial scaffold stage:

- `index.js` registers the root component (`App`, from `App.tsx`) under the app name defined in `app.json` via `AppRegistry.registerComponent`. This is the sole native/JS entry point on both platforms.
- `App.tsx` wraps the app in `SafeAreaProvider` (from `react-native-safe-area-context`) and reads `useSafeAreaInsets` to pass insets down — any new top-level UI should stay inside this provider to get correct safe-area handling on notched devices.
- `android/` and `ios/` contain the native project shells (Gradle / Xcode + CocoaPods) generated by the CLI. Native code changes belong here; JS/TS logic belongs at the repo root.
- Path aliases/module resolution: none configured — Metro uses `@react-native/metro-config` defaults with no custom `resolver` settings in `metro.config.js`.
- TypeScript config (`tsconfig.json`) extends `@react-native/typescript-config`; Babel config extends `@react-native/babel-preset`. Don't add custom transforms/aliases without updating both if JS behavior needs to match TS resolution.
- Linting extends `@react-native` ESLint config (`.eslintrc.js`); formatting rules (`.prettierrc.js`) use single quotes, trailing commas everywhere, and `avoid` arrow-paren style — match these when writing new code.
- Tests use `@react-native/jest-preset` with `react-test-renderer`; `__tests__/App.test.tsx` is the only test currently and just smoke-renders `App`.

Requires Node >= 22.11.0 (per `package.json` `engines`).
